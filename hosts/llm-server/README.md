# LLM server monitoring (exporters + Grafana dashboard)

Grafana dashboard **LLM Servers / LLM Server Overview** (`uid: llm-server-overview`) shows, per LLM
server: the served model, tokens/s, GPU and host metrics. The LLM servers run outside k3s, so the
exporters are installed on each host with `install-exporters.sh`; Prometheus scrapes them with
static targets.

## Components

| Component | Where | Port | Source / version | Metrics |
|---|---|---|---|---|
| llama-server `--metrics` | LLM host (already running) | 8080 | llama.cpp | `llamacpp:*` (tokens, t/s, requests, MTP drafts) |
| prometheus-node-exporter | LLM host, systemd `prometheus-node-exporter.service`, user `prometheus` | 9100 | Ubuntu apt, 1.10.2-1 | `node_*` (CPU, RAM, swap, disk, network, temperatures) |
| llm-model-info | LLM host, `llm-model-info.timer` (every 10 s) → `llm-model-info.service` (oneshot, user `prometheus`) | – (textfile collector of node-exporter) | this folder | `llm_*` (model alias/file/quant/build, context, parameters, size, context-window usage per slot) |
| nvidia-gpu-exporter | LLM host, systemd `nvidia_gpu_exporter.service`, user `nvidia_gpu_exporter` | 9835 | [utkuozdemir/nvidia_gpu_exporter](https://github.com/utkuozdemir/nvidia_gpu_exporter) 1.17.0 (`.deb`, sha256-pinned) | `nvidia_smi_*` (utilisation, VRAM, temperature, power, clocks) |
| Prometheus jobs `llm-node`, `llm-gpu-nvidia`, `llm-llamacpp` | `kubernetes/prometheus/configmap.yml` | – | – | adds label `server` to every target |
| Dashboard | `kubernetes/grafana/dashboard-llm-server-configmap.yml` (ConfigMap `grafana-dashboard-llm-server`) | Grafana 3000 | generated by `scripts/gen-llm-server-dashboard.py` | – |
| Grafana provider `llm-servers` | `kubernetes/grafana/dashboard-provider-configmap.yml` | – | – | folder `LLM Servers`, path `/var/lib/grafana/dashboards/llm-servers` |

## Files in this folder

| File | Installed to | Purpose |
|---|---|---|
| `install-exporters.sh` | – (run once) | idempotent installer, run as root |
| `llm-model-info.py` | `/usr/local/bin/llm-model-info` (0755) | reads llama-server `/props` + `/v1/models` + `/slots`, writes `llm_model.prom` atomically |
| `llm-model-info.service` | `/etc/systemd/system/` (0644) | oneshot, sandboxed (`ProtectSystem=strict`, `ProtectHome=yes`, `NoNewPrivileges=yes`) |
| `llm-model-info.timer` | `/etc/systemd/system/` (0644) | `OnBootSec=10s`, `OnUnitActiveSec=10s` |

| Variable | Used by | Default | Meaning |
|---|---|---|---|
| `NGX_VERSION` | `install-exporters.sh` | `1.17.0` | nvidia-gpu-exporter release |
| `NGX_SHA256` | `install-exporters.sh` | `1bc0f7f811579a7505ed284e9cdcea1a454f3101da2c60877a7aaafb15fecde4` | sha256 of the amd64 `.deb` (change together with `NGX_VERSION`) |

| `TEXTFILE_DIR` | `llm-model-info`, installer | `/var/lib/prometheus/node-exporter` | node-exporter textfile collector directory (Ubuntu package default), owner `prometheus:prometheus`, 0755 |

### `llm_*` metrics

| Metric | Labels / value |
|---|---|
| `llm_server_up` | 1 = llama-server answered `/props`, 0 = not reachable (all other `llm_model_*` are then absent) |
| `llm_model_info` | labels `alias`, `model_file`, `model_repo`, `quant`, `build`; value 1 |
| `llm_model_context_size` | configured context (`-c`), tokens |
| `llm_model_context_train` | trained context of the model, tokens |
| `llm_model_slots` | parallel slots (`-np`) |
| `llm_model_parameters` | parameter count |
| `llm_model_size_bytes` | weights size |
| `llm_model_sleeping` | 1 if llama-server reports `is_sleeping` |
| `llm_slot_context_tokens{slot}` | tokens held in the slot context = `/slots` `n_prompt_tokens` (prompt + generated so far; after a request it stays at the cached conversation length) |
| `llm_slot_context_size{slot}` | context size of the slot (`/slots` `n_ctx`) |
| `llm_slot_processing{slot}` | 1 while the slot processes a request |
| `llm_slot_decoded_tokens{slot}` | tokens generated so far by the running request (0 when idle) |
| `llm_model_info_last_run_timestamp_seconds` | unix time of the last run |

`llm_slot_*` are absent when llama-server runs with `--no-slots` (`/slots` disabled).

## Install on a new LLM host (Ubuntu, NVIDIA, llama-server on :8080 with `--metrics`)

```bash
scp -r hosts/llm-server <user>@<host>:llm-exporters
ssh <user>@<host> 'sudo bash ~/llm-exporters/install-exporters.sh'
curl -s http://<host>:9100/metrics | grep ^llm_     # model info
curl -s http://<host>:9835/metrics | grep gpu_info  # GPU exporter
```

Then add `<host>:9100`, `<host>:9835`, `<host>:8080` with `labels: {server: '<name>-server'}` to the three
`llm-*` jobs in `kubernetes/prometheus/configmap.yml`. After ArgoCD has synced the ConfigMap, reload
Prometheus: `curl -X POST http://192.168.0.12:9090/-/reload` (`--web.enable-lifecycle` is on). The
server appears in the dashboard dropdown automatically. AMD GPUs (e.g. mr-r9700-server) need a different
GPU exporter — the GPU row stays empty until one is added.

The exporters bind to all interfaces (no auth) — LAN only, no firewall is configured on the hosts.

### Uninstall

```bash
sudo systemctl disable --now llm-model-info.timer
sudo apt purge prometheus-node-exporter nvidia-gpu-exporter
sudo rm /usr/local/bin/llm-model-info /etc/systemd/system/llm-model-info.service /etc/systemd/system/llm-model-info.timer
sudo systemctl daemon-reload
```

## Dashboard

Variables: `datasource` (Prometheus), `server` (`label_values(up{job=~"llm-.*"}, server)`). Refresh 30 s,
default range 6 h.

| Row | Panels |
|---|---|
| Model & status | alias, model file, quant, parameters, weights size, context, llama.cpp build, llama-server up/down, host uptime; generation t/s (now and range average), prompt t/s, tokens generated, prompt tokens, MTP acceptance, active requests, context peak |
| Tokens per second | **Tokens per second** chart (generation t/s, effective throughput t/s, prompt t/s on right axis), MTP draft acceptance %, tokens per minute, requests processing/deferred |
| Context window | context used % (gauge), tokens in context, tokens free, slot busy, tokens generated by the running request; usage % over time with the peak since llama-server start |
| GPU | name, driver, utilisation, VRAM %, temperature, power; utilisation, VRAM, temperature, power vs limit, SM/memory clocks over time |
| System | CPU, RAM, swap, disk `/`, load, CPU temperature; CPU by mode, memory, network, disk I/O over time |

Tokens/s definitions (llama.cpp exposes cumulative counters, so all values are averages over
`$__rate_interval`, ≥ 1 min at the 15 s scrape interval):

- **Generation t/s** = `rate(llamacpp:tokens_predicted_total) / rate(llamacpp:tokens_predicted_seconds_total)` — decode speed while generating; empty when idle.
- **Effective throughput** = `rate(llamacpp:tokens_predicted_total)` — generated tokens per wall-clock second; 0 when idle.
- **Prompt t/s** = `rate(llamacpp:prompt_tokens_total) / rate(llamacpp:prompt_seconds_total)` — prefill speed (cache hits excluded).
- **MTP acceptance** = `rate(..spec_decode_num_accepted_tokens_total) / rate(..spec_decode_num_draft_tokens_total)`.

Counters reset when llama-server restarts; `rate`/`increase` handle the reset.

### Edit the dashboard

Do not hand-edit the ConfigMap. Change `scripts/gen-llm-server-dashboard.py`, then:

```bash
python3 scripts/gen-llm-server-dashboard.py > kubernetes/grafana/dashboard-llm-server-configmap.yml
```
